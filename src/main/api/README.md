# main/api

**供外部程序调用的接口** —— 让别的程序（脚本、另一个应用、CI）能驱动这个启动器：
启停某个 dsh 版本、查运行状态、装/卸插件。

## 现状：**空的**

这个目录是按目标结构预留的位置，**当前没有任何实现** ——
项目至今没有对外接口。所以这里只有这份 README，没有别的文件。

写清楚这一点是有意的：一个空目录如果不说明，后来者会以为是搬迁漏了；
说清了，它就是一条待办。

## 该放什么

- 传输层：本地 HTTP / 命名管道 / Unix socket 的**服务端**；
- 协议定义：请求与响应的形状（**类型放 `@shared/types/`，不在这里**）；
- 鉴权：本机接口也要防止被任意网页调用（Origin 检查 / 随机 token）。

## 不该放什么

- **业务逻辑** —— 一律调 `domain/`。这个目录只做"把外部请求翻译成一次领域调用"；
- **渲染层的 `app://` 协议** —— 那个在 `infrastructure/protocol.ts`，服务的是本应用自己的界面；
- **`infrastructure/imageProxy.ts` 的 `/__img/`** —— 那是给渲染层用的同源图片代理，
  受 CSP 约束、只服务本窗口，不是对外接口。

## 与 `ipc/` 的区别

| | `ipc/` | `api/` |
| --- | --- | --- |
| 调用方 | 本应用自己的渲染层 | **别的程序** |
| 传输 | Electron IPC | HTTP / socket（未定） |
| 信任级别 | 同进程内的可信通道 | **不可信**，必须鉴权与限流 |

两者都是"适配层"，都只做翻译与校验，都不放业务逻辑 —— 但信任模型完全不同，
所以不合并。
