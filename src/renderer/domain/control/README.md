# renderer/domain/control

**控制页**（标签页「控制」，`/control`）—— 只回答"启哪个版本"，不承担版本管理。

| 文件 | 作用 |
| --- | --- |
| `ControlView.vue` | 版本下拉（**只列已安装的**）+ 主按钮（启动/停止）+ 检查 + 插件开关卡片 |

> 原名 `HomeView.vue`，目录原名 `runtime/`。改名是因为标签页上写的是「控制」。

## 与原版的差别（都是需求变更）

1. 顶部版本下拉只列**已安装**的版本 —— 原版列的是"远端全部版本 + 最新/已装徽标"；
2. 下方新增「插件开关」卡片（与插件页共用同一份数据）；
3. 动作按钮**只留主按钮**。原版有四个（更新/重启/卸载/启动），
   现在"更新"和"卸载"都归到版本页 —— 那里本来就是逐版本的下载与卸载。

## 「检查」会真的启动一次 dsh

它调 `diagnose:run`（主进程侧在 `main/domain/control/diagnose.ts`），
限时启动一次并解析 dsh 自己的失败诊断。**用完即停**，
但因为要真起一次，所以由用户显式点按钮触发，不自动跑。

诊断结果弹窗里被跳过的 bundle **优先展示**：桌面端模式下这就是唯一的诊断信息
（dsh 的 CLI 不接 desktop profile，拿不到 `Failed plugins` 段）。

## 弹窗为什么要 Teleport 到 body

祖先若带 `transform` / `filter` / `backdrop-filter`，`position: fixed` 会
**相对那个祖先**定位 —— 弹窗因此被困在插件卡片里并被盖住，取消按钮点不到（用户实测）。
